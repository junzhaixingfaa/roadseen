## 4. 本轮发现并修复的问题

| 编号 | 问题 | 影响 | 修复 |
|---|---|---|---|
| D01 | AI 失败时确认页隐藏输入字段 | 用户无法人工补录，勘察闭环中断 | 失败后仍展示设施特征和所有字段 |
| D02 | AI 返回值没有统一校验 | 非法枚举、越界数值可能写入地点 | 新增 `services/aiSchema.js` 统一清洗 |
| D03 | 台阶数可被写成 99 或负数 | 错误数据进入通行判断 | 前后端共同限制为 0-30 整数 |
| D04 | 事件、勘察、复核、用户 ID 使用纯毫秒时间戳 | 同一毫秒连续操作会覆盖记录 | 新增 `utils/id.js` 单调 ID |
| D05 | 收藏数据在所有账号间共享 | 演示切号后关注信息串号 | 收藏改为按账号存储，并兼容旧数据迁移 |
| D06 | 厕所开闭状态被识别但发布时忽略 | 关闭状态可能被写成开放 | 人工确认和发布均使用 `open/closed/unknown` |

## 5. 异常场景检查

- AI 超时或抛错：捕获后显示错误，不阻塞提交，字段可人工填写。
- 模型返回非布尔特征：只接受严格 `true`，字符串 `"true"` 不采信。
- 模型返回越界台阶数：清洗阶段丢弃，人工确认页再校验一次。
- 连续快速上报：ID 不再碰撞，每条事件独立保存。
- 已过期事件：自动转待复核，不会永久留在进行中。
- 发布到不存在地点：抛出明确错误，管理端显示“无法发布”。
- 无入口地点发布：只有入口全景与高差两项都经人工确认后才创建首个入口，并记录为待审核/已核验数据。
- 切换账号：订阅、收藏、最近浏览、消息已读均隔离。
